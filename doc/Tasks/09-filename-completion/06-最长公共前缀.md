## 最长公共前缀

在这一阶段，你将使用最长公共前缀处理部分补全。

### 最长公共前缀

最长公共前缀（LCP）是所有匹配条目在开头共享的最长字符串。例如：
- `xyz_foo`、`xyz_foo_bar`、`xyz_foo_bar_baz` 的 LCP 是 `xyz_foo`
- `readme.txt`、`report.txt` 的 LCP 是 `re`
- `app.py`、`data.json` 没有公共前缀（空 LCP）

当存在多个匹配时：
- 如果它们共享的前缀长于当前输入：补全到 LCP
- 如果没有：在第一次 tab 时按铃，在后续 tab 按键时列出匹配项（与前一阶段相同）

例如，如果当前目录中存在这些条目：
- `xyz_foo/`
- `xyz_foo_bar/`
- `xyz_foo_bar_baz/`

用户可以使用 LCP 渐进式补全：
```bash
$ ls xyz_<TAB>
# 补全到 LCP: xyz_foo（所有三个条目共享）
$ ls xyz_foo

# 用户输入 "_"
$ ls xyz_foo_<TAB>
# 补全到 LCP: xyz_foo_bar（xyz_foo_bar/ 和 xyz_foo_bar_baz/ 共享）
$ ls xyz_foo_bar

# 用户输入 "_"
$ ls xyz_foo_bar_<TAB>
# 只剩一个匹配，补全带尾随 /
$ ls xyz_foo_bar_baz/
```

注意尾随 `/` 仅在最后补全且恰好只剩一个匹配项时出现。

同样的逻辑适用于文件。如果条目是 `readme.txt` 和 `report.txt`：
```bash
$ cat r<TAB>
# 补全到 LCP: re（两个文件共享）
$ cat re

# 用户输入 "a"
$ cat rea<TAB>
# 只剩一个匹配，补全带尾随空格
$ cat readme.txt
#                ^
```

如果条目没有额外的公共前缀（例如 `foo` 和 `foobar/`）：
```bash
$ ls foo<TAB>
# LCP 是 "foo"，已经输入，铃响
$ ls foo<TAB>
# 列出匹配项
foo  foobar/
$ ls foo
```

### 测试

测试程序会创建嵌套条目并这样执行你的程序：
```bash
$ ./your_program.sh
```

然后它测试渐进式 tab 补全：
```bash
$ ls xyz_<TAB>
$ ls xyz_foo_<TAB>
$ ls xyz_foo_bar_<TAB>
$ ls xyz_foo_bar_baz/
```

测试程序会验证：
- 每次 tab 按键补全到剩余匹配的最长公共前缀
- 用户可以在 tab 按键之间输入额外字符以缩小匹配范围
- 只有当恰好只剩一个匹配项时才会出现尾随字符（空格或斜杠）

### 注意事项

- LCP 根据没有尾随字符的条目名称计算。只有当恰好只剩一个匹配项时才添加 `/` 或空格
- 即使 LCP 匹配完整条目名称（例如条目为 `foo` 和 `foobar/` 时的 "foo"），如果仍存在多个匹配项，也不要添加尾随字符
