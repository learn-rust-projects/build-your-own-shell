## 每个提示符前自动回收

在这一阶段，你将在每个提示符前添加自动回收。

### 每个提示符前回收

到目前为止，你的 shell 只在用户运行 `jobs` 内置命令时回收作业。在这一阶段，你将添加在每个提示符前发生的自动回收。

在打印 `$ ` 提示符之前，你的 shell 应该：
1. 检查所有后台作业，看是否有任何作业已退出
2. 为每个已完成的作业显示一行 `Done`
3. 从作业表中移除这些作业
4. 打印提示符

这意味着已完成的作业会自动出现，无需运行 `jobs`。`Done` 条目出现在命令输出和下一个提示符之间。

例如：
```bash
$ sleep 5 &
[1] 10637
$ sleep 100 &
[2] 10638

# 作业 1 完成后，运行任何命令
$ echo "Hello world"
Hello world
[1]-  Done                    sleep 5
$

# jobs 内置命令不再显示作业 1（已被回收）
$ jobs
[2]+  Running                 sleep 100 &
```

注意 `Done` 行出现在命令输出之后但在下一个提示符之前。

### 两个回收点

你的 shell 现在在两个地方回收作业：
1. **每个提示符前**：在任何命令后检查已完成的作业（前台、内置命令、后台启动，甚至空输入）
2. **jobs 内置命令内部**：在显示列表前检查已完成的作业

两个地方使用相同的回收逻辑：检查已退出的作业，显示它们为 `Done`，然后从表中移除它们。作业的 `Done` 条目恰好出现一次。或者从自动回收，或者从调用 `jobs`，以先发生的为准。

### 测试

测试程序会这样执行你的程序：
```bash
$ ./your_program.sh
```

然后它会启动多个后台作业，使某些作业退出，然后运行 `jobs` 命令：
```bash
# 启动两个后台作业
$ sleep 500 &
[1] <pid>
$ cat /path/to/fifo &
[2] <pid>

# 检查 jobs - 两个都应该正在运行
$ jobs
[1]-  Running                 sleep 500 &
[2]+  Running                 cat /path/to/fifo &

# 测试程序写入 FIFO（在单独进程中）使作业 2 退出
# 然后运行命令 - Done 行出现在下一个提示符前
$ echo banana
banana
[2]+  Done                    cat /path/to/fifo
$

# 检查 jobs - 作业 2 应被移除，只剩作业 1
$ jobs
[1]+  Running                 sleep 500 &
```

测试程序会验证：
- `Done` 行出现在命令输出之后和下一个提示符之前
- 已回收的作业从作业表中移除
- 后续 `jobs` 调用不显示已回收的作业
- 回收后标记被正确重新计算

### 注意事项

- 当作业被回收时，它恰好显示为 `Done` 一次，然后从表中移除
- 自动回收和 `jobs` 内置命令使用相同的回收逻辑
