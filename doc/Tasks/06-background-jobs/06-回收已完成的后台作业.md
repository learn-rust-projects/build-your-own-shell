## 回收已完成的后台作业

在这一阶段，你将扩展 `jobs` 内置命令来回收已完成的后台作业。

### 回收后台作业

目前，当你的 shell 中的后台进程退出时，它会变成僵尸进程——它已经运行完成但留在进程表中，直到父进程确认其退出。Shell 必须回收这些进程来清理它们。

当用户运行 `jobs` 时，你的 shell 应该：
1. 检查每个后台作业是否已退出
2. 如果作业已退出，在当前输出中显示其状态为 `Done`
3. 从作业表中移除 `Done` 作业，使其不会出现在后续 `jobs` 调用中

例如：
```bash
$ sleep 1 &
[1] 84470
# 大约1秒后，进程已退出
$ jobs
[1]+  Done                    sleep 1
# 下一个 jobs 调用不显示任何内容（作业已被移除）
$ jobs
$
```

注意 `Done` 条目没有尾随的 `&`，而 `Running` 条目有。

### 检测进程退出

检查每个后台作业是否已退出的机制取决于你的语言，但总体方法是检查进程状态而不等待它完成。

例如：
- 在 C/Unix 中：使用 `waitpid(pid, &status, WNOHANG)` 并检查 `WIFEXITED(status)`
- 在 Python 中：使用 `subprocess.Popen.poll()` 并检查返回码是否为 `None`
- 在 Node.js 中：监听子进程上的 `exit` 事件

在这一阶段只处理正常退出。不必担心被信号终止或停止的进程。只检测进程何时正常退出。

### 测试

测试程序会这样执行你的程序：
```bash
$ ./your_program.sh
```

然后它会启动一个后台作业并用 `jobs` 检查它：
```bash
$ cat /path/to/fifo &
[1] 84470
$ jobs
[1]+  Running                 cat /path/to/fifo &
$
```

测试程序会写入 FIFO 使 `cat` 进程退出：
```bash
$ echo -ne "" > /path/to/fifo
```

下一个 `jobs` 调用应显示已完成的作业：
```bash
$ jobs
[1]+  Done                    cat /path/to/fifo
```

以下 `jobs` 调用应不显示任何内容：
```bash
$ jobs
$
```

测试程序会验证：
- 第一个 `jobs` 调用显示作业为 `Running` 并带有尾随 `&`
- 第二个 `jobs` 调用显示作业为 `Done` 且没有尾随 `&`
- 第三个 `jobs` 调用不显示任何作业（已完成的作业已被移除）

### 注意事项

- 在这一阶段你只需要处理单个后台作业
- 只检测正常退出（进程正常退出）。不处理信号终止或停止状态
