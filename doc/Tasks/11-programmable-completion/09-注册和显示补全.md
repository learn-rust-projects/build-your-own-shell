## 注册和显示补全

在这一阶段，你将添加支持使用 `-C` 标志注册补全并扩展 `-p` 显示补全。

### 注册和显示补全

`-C` 标志告诉 `complete` 为命令注册一个补全脚本。一旦注册了补全，`complete -p <command>` 应该以规范化格式打印它。

```bash
$ complete -C /path/to/git/completer git
$ complete -p git
complete -C '/path/to/git/completer' git

$ complete -C /path/to/docker/completer docker
$ complete -p docker
complete -C '/path/to/docker/completer' docker
```

关于输出格式有两点需要注意：

- 脚本路径用单引号括起来
- 参数之间恰好用一个空格分隔，无论注册命令是如何编写的

所以即使用户用额外空白注册，输出始终是干净的：

```bash
$ complete   -C    /path/to/git/completer   git
$ complete -p git
complete -C '/path/to/git/completer' git
```

### 测试

测试程序会这样执行你的程序：

```bash
$ ./your_program.sh
```

它会用 `-C` 注册补全（有时使用额外空白），然后用 `-p` 查询：

```bash
$ complete  -C  /path/to/completer/script  git
$ complete -p git
complete -C '/path/to/completer/script' git

$ complete   -C /path/to/docker/completer    docker
$ complete -p docker
complete -C '/path/to/docker/completer' docker
```

测试程序会验证：

- `complete -C <path> <command>` 注册补全且不产生输出
- `complete -p <command>` 以格式 `complete -C '<path>' <command>` 打印注册的补全
- 输出在路径周围使用单引号，参数之间使用单空格

### 注意事项

- 在前面的阶段中，`complete -p <command>` 打印 `complete: <command>: no completion specification`。当给定命令没有注册补全时，该错误仍然是正确的响应
- 不要回显原始 `complete -C` 命令。解析参数，存储它们，并以规范化格式重建输出
- 路径周围的单引号是输出中的字面字符
