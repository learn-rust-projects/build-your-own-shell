## 传递环境变量

在这一阶段，当调用补全脚本时，你将传递 `COMP_LINE` 和 `COMP_POINT` 作为环境变量。

### 补全环境变量

在前面的阶段中，你将命令名、当前单词和前一个单词作为参数传递给补全器。有些补全器还需要知道完整命令行和光标位置。你的 shell 应在调用补全器之前设置两个环境变量：

- `COMP_LINE` — TAB 按下时命令行的完整文本（无尾随换行符）
- `COMP_POINT` — 光标位置在 `COMP_LINE` 中的零基字节索引。当在行尾按 TAB 时，这是 `COMP_LINE` 的长度

例如，如果用户输入：

```bash
$ git ad<TAB>
```

你的 shell 应该设置：

- `COMP_LINE`: `git ad`
- `COMP_POINT`: `6`（字符串 `git ad` 是 6 字节长，光标在末尾）

这些与前面的阶段中的 `argv[1]`、`argv[2]` 和 `argv[3]` 参数一起，作为环境变量设置在补全器进程上。

### 测试

测试程序会这样执行你的程序：

```bash
$ ./your_program.sh
```

然后它会注册一个补全脚本并触发补全：

```bash
$ complete -C /path/to/completer_script git
$ git ad<TAB>
$ git add
```

补全脚本依赖 argv 参数和环境变量来产生正确的候选项。如果 `COMP_LINE` 或 `COMP_POINT` 缺失或错误，脚本将不会返回正确结果，补全将失败。

测试程序会验证：

- `COMP_LINE` 设置为 TAB 按下时完整命令行文本
- `COMP_POINT` 设置为光标位置的正确字节索引
- 补全结果正确（确认两个环境变量都正确传递）

### 注意事项

- `COMP_POINT` 是字节索引，不是字符索引。对于 ASCII 输入，它们是相同的，但如果你处理多字节字符，区别就重要了
- 这些环境变量应该只为补全器进程设置，不要持久化到你 shell 自己的环境中
