不转义时，字符会按“语言/解析器预定义的语义”解释。

也就是说：

> 某些字符不仅仅是字符，
> 而是“控制符”“语法符号”“元字符”。

这就是为什么需要转义。

---

# 1. 字符有两种身份

以：

```text id="u3d0t6"
"
```

为例。

它可以是：

## 普通字符

表示：

```text id="ayqfpo"
双引号本身
```

也可以是：

## 语法符号

表示：

```text id="6fgg0p"
字符串开始/结束
```

---

# 2. 为什么不转义会出问题

例如：

```js id="dr2w6y"
const s = "hello "world"";
```

解析器看到：

```text id="m6vkj2"
"
```

默认语义是：

> 字符串边界

因此它理解成：

```js id="gt5o35"
"hello ";
```

字符串已经结束。

后面的：

```text id="1e0f9r"
world
```

变成非法 token。

# 4. 字符串中的特殊字符

## `"`

### 不转义

```text id="6jsl84"
"
```

表示：

> 字符串结束

---

## `\`

### 不转义

```text id="5l3ms0"
\
```

表示：

> 后面字符需要特殊解释

例如：

```text id="ezmx6h"

```

换行。

---

## `\n`

### 不转义时

表示：

> 换行控制字符

不是：

```text id="e9k5wb"
\ + n
```

---

## `\t`

表示：

> Tab

# 5. 正则表达式里的特殊含义（非常重要）

正则表达式本质就是：

> 一门小型 DSL（领域语言）

因此很多字符是“元字符”。

---

## `.`

### 不转义

```regex id="3jbx67"
.
```

表示：

> 任意字符

---

## `*`

### 不转义

```regex id="6xdv1k"
a*
```

表示：

> 前面的字符重复 0~∞ 次

---

## `+`

### 不转义

```regex id="w14tpf"
a+
```

表示：

> 至少一次

---

## `?`

### 不转义

```regex id="sr7cgd"
a?
```

表示：

> 0 或 1 次

---

## `[]`

### 不转义

```regex id="yw8e6j"
[a-z]
```

表示：

> 字符集合

---

## `()`

### 不转义

```regex id="vf22r9"
(ab)
```

表示：

> 分组捕获

---

## `\d`

### 不转义

```regex id="94md9f"
\d
```

表示：

> 数字字符

# 9. SQL 中不转义的含义

# 10. 本质：字符不仅是数据，还是语法

这是关键认知。

---

## 普通字符

例如：

```text id="fzyfj2"
a
b
1
2
```

通常只是数据。

---

## 特殊字符（Meta Character）

例如：

```text id="6jg2n6"
"
\
*
+
?
$
<
>
```

它们会：

- 改变解析流程
- 改变语法树
- 改变控制逻辑

# 11. 从编译器角度理解

例如：

```js id="p2kg6n"
"abc";
```

Lexer 会生成：

```text id="z57c5n"
STRING_TOKEN
```

而：

```js id="sqthm4"
"abc"def
```

会变成：

```text id="8ujrli"
STRING_TOKEN + IDENTIFIER
```

因为：

```text id="pww6wb"
"
```

默认语义是：

> token 边界

---

# 12. 为什么反斜杠被选为转义符

因为：

```text id="72ahh8"
\
```

在大多数文本中出现频率低。

适合作为：

> “控制前缀”

即：

```text id="1ozs9n"
escape prefix
```

---

# 13. 一个统一视角（核心）

可以把：

## 不转义字符

理解成：

> “按语言语法解释”

而：

## 转义字符

理解成：

> “按字面值解释”

# 总结

## 不转义时发生什么

字符会按：

```text id="ihhprl"
语言预定义语法
```

解释。

它们不是普通字符，而是：

- 元字符（meta character）
- 控制符
- 语法标记
- token 边界

---

## 高价值知识点

### 1. “特殊字符”本质是语法控制符

例如：

- regex 元字符
- SQL 字符串边界
- HTML 标签
- Shell 通配符

---

### 2. 转义的本质

转义不是“加个斜杠”。

而是：

> 强制按字面值（literal）解释字符

---

### 3. 编译原理角度

字符先经过：

```text id="vlh9d2"
Lexer → Parser
```

特殊字符会改变：

- token 划分
- AST 结构
- 语义行为

---

### 4. 安全问题核心

大量注入漏洞本质：

> 用户输入被当成语法，而不是数据

这是：

- SQL Injection
- XSS
- Command Injection

的根因。

---

### 5. 最重要的方法论

看到特殊字符时，先问：

```text id="qmq3t6"
当前上下文里，
它是“数据”还是“语法”？
```

这是理解：

- 编译器
- 正则
- SQL
- HTML
- Shell
- JSON

的统一思维模型。
